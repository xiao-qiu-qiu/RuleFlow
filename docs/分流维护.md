# 分流与订阅生成维护

`template/clash-self.yaml` 是自写 Mihomo 模板，业务组默认跟随手动选择。它引用当前 RuleFlow 部署里的 `need_proxy` 和 `reject_*` 自建规则源；在其他实例使用前需要先配置对应规则源。模板不包含节点或订阅凭据。

ChinaMax 使用官方完整的 `ChinaMax_Classical.yaml`，配置为 `behavior: classical`、`format: yaml`。基础 `ChinaMax.yaml` 需要配合 Domain/IP 两份文件使用，不应单独当作完整国内名单。参考 [ChinaMax 官方说明](https://github.com/blackmatrix7/ios_rule_script/blob/master/rule/Clash/ChinaMax/README.md)。

## 路由行为

- 规则从上到下匹配，显式代理规则可能先于 CN IP 直连命中；IP 地理标签本身不会覆盖规则顺序。
- `no-resolve`、`src` 是规则选项，不是策略名。生成器应保留这些合法规则，以及逻辑规则和 `SUB-RULE` 引用。
- 模板的首项默认选择不会强制覆盖客户端 `store-selected` 保存的历史选择；更新订阅后应确认业务组当前指向手动组。
- 固定格式策略请求不兼容的通用订阅格式时返回明确错误；需要一个链接用于多类客户端时使用 `adaptive`。Mihomo/Stash 转 V2Ray 链接仍受支持。
- Surge 不支持 VLESS；混合订阅仅导出可用节点，全部节点不兼容时返回错误，避免产生空测速组。

## 更新与缓存

修改、重新导入、删除、批量启停节点后，生成配置缓存会失效。同步订阅时，在旧节点 ID 被重映射前收集受影响策略，更新引用成功后清缓存；从上游消失或被过滤的节点会移除旧引用。策略节点 ID 的重映射在数据库事务内提交。

订阅源的排除关键词、排除正则与协议白名单在同步准备阶段应用。无效正则或过滤后没有可用节点时会报错，并保留现有节点与策略选择，避免误配过滤条件清空已有选择。

## 公开转换接口

公开 `/convert` 只允许读取公开模板和公网 HTTP/HTTPS 订阅。DNS 解析、实际连接地址与重定向都进行地址检查，禁用会绕过检查的环境代理。后台管理的订阅源仍可连接管理员配置的私有服务。

订阅和规则源响应解压后上限为 64 MiB；同时支持 gzip、zlib DEFLATE、原始 DEFLATE。同步日志不记录完整订阅 URL 或策略 token。

## 验证

关键回归包含生成后完整规则保留、Surge 节点与逻辑规则、压缩响应、公开地址与重定向限制、同步过滤及重映射缓存失效。运行：

```sh
go test . ./api ./cache ./config ./database ./internal/... ./services
```

生产更新后，应检查实际 `/universal-sub` 输出，而不只检查数据库模板：确认 CN IP 规则仍在输出、ChinaMax URL 正确、业务组首项正确，最后让客户端更新订阅并确认实际命中规则。
